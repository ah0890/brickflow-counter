# Security and privacy review

BrickFlow is a single-user, local application. The review assumes the operator is trusted, but uploaded videos and their file names are not.

## Measures

| Area | Risk | Measure |
| --- | --- | --- |
| Network exposure | Others on the LAN reach the app | Streamlit binds to `localhost` only (`.streamlit/config.toml`). Exposing it requires an explicit config change. |
| Telemetry | Usage or footage leaving the machine | Streamlit usage stats disabled; Ultralytics runs with `YOLO_OFFLINE=1` (no analytics, no automatic downloads). No cloud calls. |
| Uploads | Oversized, disguised or malformed files | Extension allow-list, size limit (checked before and after upload), container signature must match the extension, first frame must decode, duration limit. Rejected files are deleted. |
| File names | Path traversal, overwriting files | Uploads are stored under a generated job ID, never under the original name. Every read/delete of outputs and samples goes through `resolve_within` (blocks `..`, absolute paths and symlinks escaping the base folder). |
| Temporary files | Footage left on disk | A replaced upload is deleted immediately; stale uploads are removed at startup after `paths.temp_max_age_hours`. |
| Model weights | `.pt` files are pickles and can run code when loaded | Only files in `models/` can be selected in the UI. The README warns to load only trusted weights. |
| HTML rendering | Script injection via names | All custom HTML escapes its values with `html.escape`; user-supplied names in Markdown are escaped (`md_escape`). |
| CSV reports | Spreadsheet formula injection via file names | Cells starting with `= + - @`, tab or CR are prefixed with `'`. |
| Subprocess | Command injection in ffmpeg call | Fixed argument list with no shell. Paths are generated by the app. A timeout is set. |
| Resource use | Very long videos tie up the machine | Duration and size limits; one job per session; cancel stops between frames. |
| Dependencies | Known vulnerabilities | `pip-audit -r requirements.txt` (2026-11-04): no known vulnerabilities. The local venv's `setuptools` (build tool, not a runtime dependency) was upgraded to clear PYSEC-2025-49 / PYSEC-2026-3447 / GHSA-xmj3-9gf7-h52w. `torch` CPU wheels cannot be audited from PyPI; keep them current. |

## Out of scope / residual risk

- No authentication: anyone with access to the local machine's browser session can use the app. Do not expose it on a network without adding authentication and HTTPS (e.g. a reverse proxy).
- Video decoding uses OpenCV/FFmpeg. A malicious file could target decoder vulnerabilities, so keep `opencv-python` and `imageio-ffmpeg` updated.
- Outputs are kept until deleted manually; they may contain footage of people.
